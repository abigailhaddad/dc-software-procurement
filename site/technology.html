Which codes count

Every contract and purchase order on DC's site carries a commodity code from the NIGP list, a standard catalogue of goods and services used by state and local governments. The first three digits are the class ("208: computer software for microcomputers"); the full seven-digit code names the item. This page counts only records whose codes are listed below: no keyword search, no categories of our own. Contracts and purchase orders are never added together, because an order can be placed under a contract and would count the same purchase twice.

Class descriptions are from the District's NIGP class list; item descriptions are as DC's contract pages show them. Counts here are per code and don't change with the ticks.

Before you use these numbers

The code is whatever was entered with the record, and it can be wrong. Software licences turn up under consulting (918) and library and subscription services (956); copier service turns up under computer maintenance (939); one contract for IBM software licences is coded as a professional licence renewal. How much this matters is measured below.

This is a known problem. In April 2019 the District's Inspector General found that OCTO had not reviewed about $152 million in technology requisitions, partly because agencies could pick non-technology commodity codes and so skip its review (OIG report 18-1-19TO; see How DC buys).

Each record is counted once. A contract can carry several codes. Like the rest of the site, this page uses the codes DC's search listing shows for each option period. An option period is in if any of its codes is in a ticked group. A purchase order has one code. A contract counts once in the totals however many option periods it has, and its dollars are its base-period amount only.

The contract's own page on DC's site can list more codes than the search listing does. In the 12 October 2026 pull, 22 contracts carried a code from the class groups only on their own page (for example CW93000, Emphasys software, listed under consulting). They are counted only if a listing code puts them in a group.

The vendor is whoever holds the contract, often a reseller. The vendor and supplier tables show sellers, not software makers: Carahsoft, for example, is the vendor on DC's contracts for Acquia's Drupal licences (CW86957) and Salesforce licences (CW92708).

How well do the codes catch technology?

Partly. On 12 October 2026 we read the titles of two random samples of contracts, drawn using the whole-class groups alone. Of 20 drawn from those classes, 18 were plainly technology purchases, one was copier and print service, and one (“Document Systems OY4”) we could not tell from the title. Then we drew 20 from the 337 contracts outside those classes whose titles use words such as software, licence, system, platform, network or computer. 14 of those were technology purchases, such as Salesforce, IBM and Esri licences and Dell computers. Hence the item-code groups: the cloud-subscription and other-item groups catch 8 of those 14, and the computer-consulting group 3 more. The other 3 (IBM licences coded as a professional licence renewal, a voter registration database, Dell computers coded as publications) no code-based rule would catch. These are samples of 20, read by title only.
